**Created:** 2026-10-22 · **Status:** decided · **Authority:** ssot for the 7.3 release

structure: popular Claude Code plugin READMEs checked the same day (same file, §README practice).
**Review:** medium · a fix round inside a decided design, plus docs · `/code-review` medium on the merged diff (high on
the hooks: they gate secrets), the integrator re-runs every gate; the owner reads the README.

## Goal

Fix every defect the 2026-10-22 audit confirmed, bring the kit up to the practice its maintainer runs today, and
rebuild the front page so a newcomer sees in one scroll what the kit is, what is inside the plugin (every skill,
agent, hook, rule template, reference and template), how it fits together (current diagrams), and how to start.

## Non-goals

- No new memory layer, no new always-loaded rule beyond the orchestration template the user opts into.
- No host promoted to a higher tier without a live probe (no Codex/Copilot/Cursor/OpenCode CLI on this machine).
- No push to `origin` without the owner's yes (every push to main becomes an Anthropic-directory version).
- The demo recordings are not deleted from `.github/assets/` (the launch post may use them); they leave the README flow.

## Amendment 2026-10-22 — the append exemption (security review of 3a5a906)

AC-17: the `>> .env` exemption in `guard-secrets.py` covers ONLY a plain stdout append (`>>`, `1>>`, `&>>`); `N>>` for any
other fd stays blocked; and any command that has a secret-named append target AND an argv word naming a file descriptor
path (`/dev/fd/*`, `/dev/stdin|stdout|stderr`, `/proc/<self|pid>/fd/*`) is blocked — on Linux reopening the fd path reads
the file back (`cp /proc/self/fd/1 /tmp/x >> .env`). Tests for each bypass shape, red before the fix. Owner: S1.

## Amendment 2026-10-22 — code review (high) of release/7.3, adjudicated

Accepted (fix round R2, executor, worktree `release/7.3-r2`):
- R2-1 the guard pre-check proves python3 RUNS, not only exists: `python3 -c 'import sys; sys.exit(sys.version_info < (3,9))' >/dev/null 2>&1 || exit 0; python3 …` (the macOS `/usr/bin/python3` stub exists, exits 1 → with `onFailure: block` every call would be blocked). check-repo §3 requires this form. All three guards use it.
- R2-2 the opening-section picker: a heading of level ≥ 2 whose text STARTS (after optional numbering, `[`, punctuation) with "opening"; headings inside fenced code are ignored; no match → the plain cut.
- R2-3 the opening section itself is capped at HANDOFF_INJECT_CAP (cut with the existing marker); the handoff body never exceeds the cap.
- R2-4 legacy_hooks `_scripts`: expand `$CLAUDE_PROJECT_DIR` / `${CLAUDE_PROJECT_DIR}` (quoted or not) to the project dir, then split with `shlex` (posix) so quoted paths with spaces resolve; tests for the docs' recommended form and a path with a space.
- R2-5 compaction nudge: only a READ-ONLY part consults the seen file; the writer consumes the marker and never re-reads the seen file; a second compaction over saved memory gives no warning (test).
- R2-6 protect-tests: the statefs import is guarded like session-start's — a missing lib degrades the ledger to best-effort, never kills the guard.
- R2-7 guard-zsh-split: a prefix assignment (`NAME=v cmd`) does not set NAME for later commands; a substitution in an assignment's value is walked after the assignments before it.
- R2-8 guard-zsh-split: nesting past the depth raises `cmdparse.NestingError` → `ask`, like the other guards; docstring corrected.
- R2-9 guard-secrets: the literal-append exemption is computed only when a secret redirect target is found.
Rejected: "zsh guard blocks `cd $d` with a spaced path" — the source hook's measurement on 46,420 real commands
(177 blocks, 0 false) outranks a constructed example; `# zsh-split-ok` covers the rare intended case.

Deviations registered at merge (R2, all accepted): pre-compact.sh also drops the stale seen-file (closes the read-only
parts' repeat); check-repo §3 rejects `command -v` in every hook; the opening label no longer promises "whole"; the
legacy-hook script search made linear (was quadratic) — one piece holding two scripts yields the first; the executor's own
